You want API regressions caught before merge, not after users find them. I built Doppel, a GitHub Action that runs every pull request against main in sandboxes, replays the same requests through both versions, and shows the exact response that changed. It works with FastAPI, Flask and Django apps, uses pytest suites as-is, and an LLM judge filters out changes the PR announces. On a 30-PR benchmark, tests plus Doppel caught 20 of 20 regressions, against 12 for the tests alone. I haven't shipped Docker-based setups in Doppel itself (it uses Nebius sandboxes), but packaging the check in a container is straightforward.
